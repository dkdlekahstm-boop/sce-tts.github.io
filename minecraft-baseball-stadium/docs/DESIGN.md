# Minecraft Bedrock 야구 경기장 — 설계 문서

> 대상: **Minecraft Bedrock Edition** (모바일 Android/iOS 포함, 최신 버전 기준 `@minecraft/server` 1.x / `@minecraft/server-ui` 1.x Script API)
> 목표: 무료 애드온(`.mcaddon`)만 설치하면 로비 → 인원/팀 선택 → 9이닝 경기까지 **자동으로** 진행되는 플레이 가능한 야구 맵.

이 문서는 코드를 쓰기 전에 반드시 지켜야 할 두 가지를 먼저 확정한다.

1. **실제 좌표/치수** — 아래 좌표는 모든 `.mcfunction`/`.js` 파일이 참조하는 단일 진실 소스(SSOT)다. `scripts/constants.js` 의 값과 100% 동일해야 한다.
2. **Bedrock에서 실제로 되는 것 vs 안 되는 것** — 요청하신 기능 중 일부는 Bedrock 공개 API에 존재하지 않는다. 존재하지 않는 API를 지어내는 대신, 아래에서 "대체 구현 방식"을 명시하고 그 방식으로 코드를 작성했다.

---

## 1. 전체 시스템 구조

```
플레이어 입장
   └─ 로비 영역 (스폰) : ActionFormData UI
        ├─ [게임 시작] 버튼(NPC/사인 우클릭 or 아이템 사용)
        ├─ 인원 선택 (1/2/3인)
        ├─ 홈팀/원정팀 선택
        └─ gameManager.startGame()
                ├─ fielding.js   : 9개 수비 포지션에 NPC/플레이어 배치, 사람 부족분 NPC로 채움
                ├─ pitching.js   : 투수 턴 - 구종/코스 선택 UI → 공 엔티티 투척
                ├─ batting.js    : 타자 턴 - 스윙 입력 판정 → 결과 산정
                ├─ baserunning.js: 타구 결과에 따라 주자 자동 진루/아웃
                ├─ rules.js      : 볼/스트라이크/아웃/이닝/득점 규칙 엔진 (상태머신)
                ├─ scoreboard.js : 전광판(armor stand 텍스트) + 사이드바 scoreboard 갱신
                └─ crowd.js      : 관중 연출(사운드/파티클), 이닝 종료 시 다음 이닝
```

`main.js` 는 world 초기화(1회) + `system.runInterval` 틱 루프만 담당하고, 나머지는 각 모듈이 이벤트 기반으로 반응한다. 상태는 전부 **world dynamic property** 또는 **scoreboard**에 저장해 서버 재시작에도 안전하게 했다 (in-memory 변수만 쓰면 스크립트 리로드 시 경기 상태가 날아간다).

## 2. 경기장 좌표 설계 (SSOT)

Y축은 빌드 기준면 `GROUND_Y = 5`(초기화 시 스크립트가 해당 구역을 평탄화하고 베드락으로 바닥을 깐다. 어느 월드에 심어도 동일하게 보이도록 하기 위함).

베이스 다이아몬드는 **X/Z 축에 정렬된 정사각형**으로 배치한다 (홈→1루→2루→3루가 각각 +X, +Z 방향). 실제 다이아몬드를 45°로 돌려 짓는 대신 이렇게 하면 `fill` 계열 명령으로 라인/구역을 정확히 그릴 수 있어 모바일에서도 안정적으로 생성된다. 외야는 홈플레이트를 중심으로 1사분면(+X,+Z) 쪽 부채꼴로 펼쳐지며, 1루측 파울라인은 +X축, 3루측 파울라인은 +Z축과 일치한다.

| 요소 | 좌표 (X, Y, Z) | 비고 |
|---|---|---|
| 홈플레이트 중심 | (0, 5, 0) | 오각형 5블록으로 표현 |
| 1루 | (27, 5, 0) | 베이스패스 27블록 ≈ 실제 90ft |
| 2루 | (27, 5, 27) | |
| 3루 | (0, 5, 27) | |
| 투수판(마운드 중심) | (13, 5, 13) | 홈-2루 대각선상 45° 지점, 실제 60.5ft 근사, 마운드는 반경 3, 높이 +1 |
| 우익 파울폴 | (60, 5, 0) | X축상, 펜스 시작점 |
| 좌익 파울폴 | (0, 5, 60) | Z축상 |
| 중견수 펜스 정점 | (56.6, 5, 56.6) | 홈에서 45°, 거리 80 |
| 백스톱(그물) | 홈 뒤 (−8 ~ −1, Z −8~−1 대각) | 홈 뒤쪽 부채꼴, 높이 6 |
| 홈팀 덕아웃 | (−14, 3, −4) ~ (−4, 6, 10) | 지면보다 2블록 낮게(반지하) |
| 원정팀 덕아웃 | (−4, 3, −14) ~ (10, 6, −4) | 대칭 배치 |
| 불펜 | 각 덕아웃 뒤 6×4 구역 | 투수 NPC 대기 |
| 관중석(스탠드) | 반경 63~105, 0°~360° (입구용 40° 구간 제외) | 4단, 단마다 +2블록 높이/계단 |
| 조명탑 | 반경 100 지점 8방位, 높이 30 | 글로우스톤 헤드 |
| 전광판(스코어보드 월) | (98, 20, 98) 부근, 홈 방향으로 회전 | armor stand 텍스트 |

`scripts/constants.js` 는 이 표를 그대로 코드화한 값이며, 실제 필드 크기는 `FIELD.OUTFIELD_R_LINE = 60`, `FIELD.OUTFIELD_R_CENTER = 80` 두 상수로 조절 가능하다.

> **왜 실제 잠실(중견수 125m) 그대로 안 짓는가?** 모바일 클라이언트는 렌더 거리/청크 로딩이 PC보다 훨씬 제한적이다. 반경 125블록 풀스케일 구장은 스탠드까지 합치면 지름 300블록 이상, 블록 수 수십만 개로 저사양 기기에서 청크 생성/렌더링 버벅임이 사실상 확정적이다. 그래서 **실제 비율(파울라인:중견수 = 100:125 ≈ 0.8)은 그대로 유지**하되 절대 크기를 60~80블록대로 축소했다. "대형 구장 느낌"은 유지하면서 모바일 최적화 요구(14번 항목)를 satisfy하기 위한 의도적 트레이드오프다.

## 3. Bedrock에서 실제로 되는 것 / 안 되는 것 (중요)

요청하신 기능을 그대로 만들 수 없는 부분은 **존재하지 않는 API를 지어내지 않고** 아래처럼 대체 구현했다.

| 요청 기능 | 실제 가능 여부 | 채택한 구현 방식 |
|---|---|---|
| 자동 진행(명령어 수동 입력 X) | ✅ 가능 | `@minecraft/server`의 `system.runInterval`, `world.afterEvents.*` 이벤트로 전부 자동화. 플레이어는 UI/아이템 조작만 함 |
| 구종/코스 선택 메뉴 | ✅ 가능 | `@minecraft/server-ui`의 `ActionFormData` (모달 폼). 폼이 열려있는 동안 해당 플레이어 입력은 일시정지되지만 매우 짧아 문제 없음 |
| "화면에 떠 있는 SWING 버튼" (HUD 오버레이 버튼) | ❌ 불가능 | Bedrock Script API는 커스텀 영구 HUD 버튼을 지원하지 않음. 대신 **아이템 사용**: 타자에게 "야구 방망이" 아이템을 쥐어주고, 투구 도중 **공을 직접 공격(attack)** 하면 `world.afterEvents.entityHitEntity` 이벤트로 스윙을 감지 |
| NPC가 임의 좌표로 실시간 길찾기 이동 | ⚠️ 부분 가능 | Bedrock에는 "좌표로 이동"을 직접 호출하는 안정 API가 없음(`entity.navigateTo` 같은 함수는 존재하지 않음). 대신 **표적 마커 엔티티**(`sce:field_target`, 투명·무충돌)를 목표 지점에 스폰하고, 수비수 엔티티의 `minecraft:behavior.nearest_attackable_target` + `minecraft:navigation.walk`가 그 마커를 "공격 대상"으로 추격하도록 behavior 파일에 정의. 도달하면 `entityHitEntity`를 "포구/베이스 터치"로 해석하고 마커를 제거. 이건 커뮤니티에서 실제로 쓰이는 정석적인 우회 기법이다 |
| 공을 실제 포물선으로 투구 | ✅ 가능 | 커스텀 프로젝타일 엔티티 `sce:baseball` + `minecraft:projectile` 컴포넌트(중력/공기저항 계수를 구종별로 다르게) + `entity.applyImpulse`로 초기 속도 부여 |
| 카메라 연출(경기 시작/홈런 등) | ✅ 가능 | `player.camera.set()/.fade()` (Script API) 및 `/camera` 커맨드. 1~2초 이내로 제한해 플레이 방해 최소화 |
| 전광판에 실시간 텍스트 (HOME 2 / AWAY 1 등) | ✅ 가능 | 화면 UI가 아니라 "월드 안의 물체"로 구현: 보이지 않는 `armor_stand` 여러 개를 전광판 벽 앞에 세우고 `nameTag`를 매 틱마다 갱신 (이름표는 항상 렌더링되고 글자 색 코드도 지원됨). 추가로 실제 화면 상단에는 `/scoreboard`의 sidebar 표시와 `onScreenDisplay.setActionBar()`로 볼/스트라이크/아웃을 보조 표시 |
| 안타/홈런 시 큰 자막 연출 | ✅ 가능 | `player.onScreenDisplay.setTitle()` (Bedrock 표준 API) |
| 도루/견제 | ✅ 가능(단순화) | 주자가 베이스 사이에 있을 때 일정 확률/타이밍으로 판정하는 로직으로 구현 (완전한 물리 판정 대신 규칙 기반) |
| 대규모 관중 애니메이션(수백 NPC) | ❌ 비권장 | 요청하신 14번 "모바일 최적화"와 정면 충돌. 실 NPC 관중은 **좌석당 1구역 최대 24체**로 제한하고, 나머지는 계단식 스탠드 블록 자체(색깔 콘크리트로 만든 "사람 형상 텍스처"는 Bedrock이 지원 안 함이므로) + 안타/득점 시 `playsound`(박수/함성)와 `particle`(색종이) 연출로 "관중이 반응하는 느낌"만 재현 |
| 완성된 `.mcworld` 더블클릭 설치 파일 | ⚠️ 부분 가능 | Bedrock의 월드 세이브(`level.dat`)는 게임 클라이언트만 생성하는 바이너리 NBT라 텍스트 코드로 안전하게 위조할 수 없다. 대신 **`.mcaddon`**(BP+RP 자동 임포트, 더블탭 설치)으로 제공한다. 경기장 건축 자체는 수동 명령어 입력이 전혀 필요 없다 — `main.js`가 월드 최초 접속 시 `system.run()`으로 자동 감지해 `stadiumBuilder.js`를 백그라운드로 실행하고, 완료 여부를 world dynamic property(`sce:stadium_built`)에 저장해 재접속 시 다시 짓지 않는다. `docs/INSTALL.md`에 설치 3단계 + 완성 후 게임 내 "월드 내보내기"로 `.mcworld`화하는 방법을 안내한다 |

## 4~18. 세부 시스템
